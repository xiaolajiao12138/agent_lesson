# 前端对应的接口练习约定

本文件只有契约，没有替你实现 Python 业务接口。下列路径统一加 `/api` 前缀。

## 公共约定

成功返回 `{ "code": 200, "message": "操作成功", "data": ... }`。HTTP 状态可为 200 或创建时的 201，成功业务码统一为 200。失败使用对应 HTTP 状态码以及 `{code,message,data:null,request_id}`。

除登录外，Axios 默认注入 `Authorization: Bearer <access_token>`。服务端需要自行验证 Token、角色、租户和数据归属，不能信任前端角色导航。

时间为带时区的 ISO 8601；金额使用整数分（89900 表示 899 元）；可空字段返回 null。完整类型在 `frontend/src/types/index.ts`。

推荐实现顺序：登录与身份 → 订单查询 → 真实模型问答 → 转人工 → 管理员审批 → 幂等及并发控制。

## 登录与身份

`POST /auth/login`：

```json
{"username":"customer","password":"123456"}
```

响应 data：

```json
{"access_token":"服务端Token","token_type":"bearer","user":{"id":"user-id","username":"customer","name":"林小满","role":"customer","tenant_id":"shop-id"}}
```

role 为 customer 或 admin。真实后端的账号密码由你设计，不必照搬前端演示凭证。

`GET /auth/me` 返回 user，刷新页面时重新验证身份。

退出登录目前清理浏览器状态；服务端 Token 撤销与退出接口由你自行扩展。

## 订单查询

`GET /orders?q=&status=&page=1&page_size=8`

- 客户只返回自己订单；管理员返回自己租户内的订单。
- status：pending_payment / paid / shipped / completed / cancelled；空字符串表示不限。
- q 匹配订单号、客户姓名或商品名称；空字符串表示不限。
- 响应 data：`{items:[Order],total:8,page:1,page_size:8}`；total 是筛选后的总数。

`GET /orders/{id}` 返回 Order：

```json
{"id":"order-id","order_no":"ORD20261127001","customer_id":"user-id","customer_name":"林小满","phone":"138****6028","address":"演示地址","items":[{"sku":"AUDIO-001","name":"无线降噪耳机","quantity":1,"price_cents":89900}],"total_cents":89900,"status":"shipped","created_at":"2026-11-27T08:00:00Z","tracking_no":"SF-DEMO-0001"}
```

路径 id 是订单主键，order_no 是面向人的订单号，两者不同。

## 真实模型问答

`POST /agent/answer`：

```json
{"message":"我的订单发货了吗？","history":[{"role":"user","content":"你好"},{"role":"assistant","content":"有什么可以帮你？"}]}
```

响应 data：

```json
{"route":"answer","message":"模型回答正文","order_id":"order-id"}
```

route 为 answer 或 transfer；order_id 可为 null。transfer 会让页面显示转人工按钮。history 只允许 user / assistant，不能允许客户端自行指定 system 指令。

当前客户端在 `request.app.state.llm_client`；模型名在 `request.app.state.settings.openai_model`。该接口由你实现。向模型提供的数据必须先经过当前用户权限过滤；模型失败应返回明确错误，不能回退到假回答。

## 转人工

`POST /tickets` 请求头包含 `Idempotency-Key`：

```json
{"question":"收到的耳机左侧没有声音，希望退换货","order_id":"order-id"}
```

question 去首尾空白后 1–2000 字；order_id 可为 null，如有关联订单则验证访问权限。创建用户与租户从 Token 获取。

同身份、同幂等键、同请求返回原申请；同 Key 不同内容返回 409。

响应 data 为 Ticket，`GET /tickets/{id}` 也返回同一结构，客户用来刷新处理进度：

```json
{"id":"ticket-id","code":"SR20261127001","order_id":"order-id","customer_id":"user-id","customer_name":"林小满","question":"希望申请退换货","status":"pending_review","version":1,"created_at":"2026-11-27T08:00:00Z","events":[{"actor":"林小满","action":"created","note":"客户提交申请","created_at":"2026-11-27T08:00:00Z"}]}
```

id 是申请编号，order_id 指向订单，code 用于展示；events 按处理时间顺序排列。

## 管理员审批

`GET /approvals?q=&status=pending_review&page=1&page_size=6`

仅管理员可用，且限制租户。data 为 `{items:[Ticket],total:1,page:1,page_size:6}`。status 支持 pending_review / approved / rejected，空字符串表示全部。按创建时间倒序。

`POST /tickets/{id}/review`：

```json
{"decision":"approved","note":"申请通过，请客服继续跟进。","version":1}
```

decision 只允许 approved / rejected；note 最长 1000 字，拒绝时必填。version 是页面读到的记录版本；记录已处理或并发版本不一致返回 409。

审批成功时，在一个事务内修改状态、version + 1、插入操作记录。响应 data 为更新后的 Ticket。通过仅记录审核决定，前端没有真实付款、退款或物流服务。
