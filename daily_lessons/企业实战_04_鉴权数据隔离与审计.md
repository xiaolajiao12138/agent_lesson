## 1. 一次请求过三道检查

1. **身份验证**。从 `Authorization: Bearer ...` 读取凭证，查出用户、租户与角色。无效或缺失时返回 401。
2. **操作授权**。审批、读取审计、管理知识库要求 `reviewer`。角色不符时返回 403。
3. **资源授权**。SQL 查询和写入都带当前身份的租户条件，普通用户还要满足所有者条件。超出可见范围时按资源不存在返回 404。

在工单审批、工单事件读取和知识库检索三个入口都要做资源授权。前端的按钮隐藏可以改善体验，权限由后端执行。API 输入模型拒绝额外字段，身份信息来自服务器配置中的凭证映射。

## 2. 关键方法与类似方案

| 方法 | 作用、输入、输出 | 类似方法与使用场景 |
| --- | --- | --- |
| `HTTPBearer(auto_error=False)` | 解析 Authorization 中的 Bearer 凭证。返回凭证对象或空值，本项目自行统一返回 401。 | `APIKeyHeader` 适合指定请求头的 API Key。`OAuth2PasswordBearer` 提取 Bearer 字符串并描述 OAuth2 password flow。各提取器都需要后续的凭证验证。 |
| `Depends(current_actor)` | 进入业务路由前执行身份验证，将可信的 `Actor` 注入参数。 | 中间件适合整个应用通用的身份上下文。依赖适合按路由组合权限，也方便测试替换。 |
| `TypeAdapter(list[IdentityInput]).validate_json(raw)` | 校验环境变量中的 JSON 列表，返回 Pydantic 身份记录列表。 | `BaseModel.model_validate_json()` 用于以对象为顶层的模型。`json.loads()` 负责解析 JSON，字段规则需要额外校验。 |
| `token_digest(token)` | 计算高熵随机凭证的 SHA-256，用哈希值查询内存身份表。 | 生产可用独立身份系统签发凭证。用 JWT 时要验证签名、颁发者、受众和过期时间。用户密码用专用密码哈希方案。 |
| `visible_ticket(session, actor, ticket_id)` | 按可信租户和资源 ID 读取；普通用户增加 owner 条件。不可见时抛业务异常。 | PostgreSQL 的 RLS 可作为第二层隔离。它需要设计数据库角色与连接池中的租户上下文，并测试绕过路径。 |

本课的凭证通过环境变量预置，教学 JSON 中的凭证是公开样例。真实环境通常用 OIDC/SSO、短时凭证、HTTPS、密钥管理和吊销机制。运行日志和数据库审计的访问权限也需要单独设计。 [OWASP Agent 安全指南](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html)

## 3. 请求日志和业务审计

| 信息 | 去哪里找 | 示例 |
| --- | --- | --- |
| 一次 HTTP 请求耗时或出错 | 应用日志，用 `X-Request-ID` 查找 | 请求 ID、路由模板、状态码、耗时 |
| 某张工单的成功变更 | 工单审计表 | 工单 ID、操作者 ID、动作、时间 |

审计与工单写入共用事务。重复请求成功重放时，业务没有发生变化，因此不会新增事件。调试日志和审计只保留必要字段，完整请求、凭证和检索内容属于需要谨慎处理的数据。
