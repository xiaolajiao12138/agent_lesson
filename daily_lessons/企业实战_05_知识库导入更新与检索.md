## 1. 先做可以量化的检索基线

Day 9–11 已经学过向量检索和引用。本项目从一组小语料开始，用明确的关键词规则稳定复现结果。调用 `POST /agent/answer` 时，先按租户和角色过滤文档，再给每份可见文档打分。命中唯一最高分时返回原文和出处。无匹配或最高分并列时返回 `transfer`，由用户确认后创建工单。

```python
normalized = question.casefold()
keywords = {keyword.casefold() for keyword in json.loads(document.keywords)}
score = sum(keyword in normalized for keyword in keywords)
```

例如“退货和物流怎么办”对退换、物流两篇文档都得到 1 分，系统建议转人工。“退换与退货怎么办”对退换文档得到 2 分。这里的分数代表关键词命中数，没有概率含义。

## 2. 每个方法具体做什么

| 方法 | 输入和输出 | 类似方法与适用场景 |
| --- | --- | --- |
| `payload.model_dump()` | 将已验证的文档输入转成字典，传给 SQLAlchemy `.values()`。 | `.model_dump_json()` 返回 JSON 字符串，适合写到文件或发送 HTTP。 |
| `json.dumps(..., ensure_ascii=False)` / `json.loads(...)` | 将关键词列表保存成 JSON 文本，读出时还原 Python 列表。 | SQLAlchemy 的 `JSON` 类型可将编解码交给驱动和类型层。PostgreSQL 的 `JSONB` 支持数据库内查询和索引。 |
| `statement.excluded[field]` | 引用发生唯一键冲突时，本次 INSERT 提供的新值。用于覆盖旧文档字段。 | `on_conflict_do_nothing()` 保留已有数据。这里用 `on_conflict_do_update()` 让资料更新可以重复导入。 |
| `str.casefold()` | 规范化大小写，适合比较多种语言中的字母。中文在这里保留原字形。 | `.lower()` 适合一般大小写转换。需要统一全角或兼容字符时，可单独评估 Unicode NFKC 规范化。 |
| `answer_question(session, actor, question)` | 返回结构化路由、回复与可选引用。可见候选在 SQL 层限制，计分在 Python 层。 | PostgreSQL 全文检索适合关键词和型号，需根据中文语料处理分词。pgvector 用于语义召回。混合检索可合并两类候选，再用 Rerank 排序。 |
| `delete(Document).where(...)` | 直接删除匹配当前租户及来源编号的记录。重复删除仍返回 204。 | 软删除适合需要恢复的场景，所有检索路径都应过滤已下架记录。版本表适合保留审批历史。 |

## 3. 文档导入、更新与下架

运行 `python -m support_agent.seed` 导入四篇样例。写入使用租户与 `source_id` 的组合主键。HTTP 的 `PUT /knowledge/{source_id}` 使用相同的更新逻辑。文档下架后，新请求立即排除它。若后续加入向量索引，需要把原文、切片、向量和权限一起更新，并验证旧版本确实退出召回。

引用中的来源 ID 由检索代码绑定到实际文档。接入 LLM 生成时，可以保留原文引用，再用人工标注和评测检查生成句子是否忠实。模型及知识文档都可能给出错误信息，工单的写操作仍通过独立授权入口执行。

## 4. 动手验收

以审批员身份修改蓝店退货规则，验证蓝店用户读到更新内容，绿店仍是原规则。下架蓝店文档后重试，确认蓝店走转人工。用固定评测集比较修改前后结果，先判断变化来自政策更新还是检索回归。

进阶题是增加“我想取消订单”与“我不想退货，我要取消订单”两条评测用例，观察子串打分在否定表达上遇到的问题，再尝试用 Day 9–11 的检索方法替换打分。
